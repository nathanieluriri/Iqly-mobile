# iOS setup for the OS surfaces (feat/os-surfaces)

None of the Swift below has been compiled: this lane had no Xcode, and CI builds Android only. project.pbxproj was not edited. Do these steps once on a Mac, build, and fix anything the compiler finds.

## What is already in the repo

- `ios/Runner/Info.plist`: CFBundleDisplayName "iQLY", NSFaceIDUsageDescription, NSSupportsLiveActivities, the `iqly` URL scheme, FlutterDeepLinkingEnabled false (surface links are routed by lib/surfaces so a cold start still passes splash and sign-in).
- `ios/Runner/Assets.xcassets/ic_shortcut_{polls,forward,submissions}.imageset`: the official icons for the app icon quick actions (generated by `dart run tool/gen_surface_assets.dart`).
- `ios/Runner/Runner.entitlements`: the App Group, not yet referenced by the target.
- `ios/RunnerSurfaces/SurfacesChannel.swift`: the method channel `net.iqly/surfaces` (publish widgets, Live Activity start/update/end, launch link).
- `ios/IqlySurfaces/`: the widget extension sources (WidgetKit widgets, ActivityKit Live Activity, generated IqColors.swift, Info.plist, entitlements, asset catalog with WidgetLogomark).
- `ios/IqlySurfaces/Shared/SurfaceShared.swift`: App Group constants and PayoutAttributes, needed by both targets.

## Steps

1. Apple Developer: create the App Group `group.net.iqly.iqlyMobile` and enable it for `net.iqly.iqlyMobile`.
2. Open `ios/Runner.xcworkspace`. File > New > Target > Widget Extension. Product name `IqlySurfaces`, bundle id `net.iqly.iqlyMobile.IqlySurfaces`, tick "Include Live Activity", untick "Include Configuration App Intent". Deployment target iOS 16.1. Delete the template Swift files and the template Info.plist / asset catalog Xcode creates.
3. Add the existing folder `ios/IqlySurfaces` to the IqlySurfaces target (Create groups, target IqlySurfaces only). Set the target's Info.plist File to `IqlySurfaces/Info.plist` and Code Signing Entitlements to `IqlySurfaces/IqlySurfaces.entitlements`.
4. Add `ios/IqlySurfaces/Shared/SurfaceShared.swift` to the Runner target as well (Target Membership: Runner and IqlySurfaces).
5. Add `ios/RunnerSurfaces/SurfacesChannel.swift` to the Runner target only.
6. Fonts for the extension: add `assets/fonts/PlusJakartaSans-Regular.ttf`, `PlusJakartaSans-SemiBold.ttf` and `BricolageGrotesque-30pt.ttf` to the IqlySurfaces target (Copy Bundle Resources). The extension Info.plist already lists them in UIAppFonts. PostScript names used: PlusJakartaSans-Regular, PlusJakartaSans-SemiBold, BricolageGrotesque30ptExtraBold.
7. Runner target > Signing & Capabilities: add App Groups (`group.net.iqly.iqlyMobile`); Xcode will point CODE_SIGN_ENTITLEMENTS at `Runner/Runner.entitlements`. Add the same capability to IqlySurfaces.
8. Embed: Runner > General > Frameworks, Libraries and Embedded Content should list IqlySurfaces.appex (Xcode adds "Embed Foundation Extensions" when the target is created). Make sure the Embed phase runs before "Thin Binary" or the Flutter build can fail with a cycle error.
9. Register the channel in `ios/Runner/AppDelegate.swift`:

```swift
func didInitializeImplicitFlutterEngine(_ engineBridge: FlutterImplicitEngineBridge) {
  GeneratedPluginRegistrant.register(with: engineBridge.pluginRegistry)
  if let registrar = engineBridge.pluginRegistry.registrar(forPlugin: "SurfacesChannel") {
    SurfacesChannel.shared.register(with: registrar.messenger())
  }
}
```

10. Forward widget and Live Activity taps in `ios/Runner/SceneDelegate.swift`:

```swift
class SceneDelegate: FlutterSceneDelegate {
  override func scene(_ scene: UIScene, willConnectTo session: UISceneSession, options connectionOptions: UIScene.ConnectionOptions) {
    super.scene(scene, willConnectTo: session, options: connectionOptions)
    connectionOptions.urlContexts.forEach { SurfacesChannel.shared.open($0.url) }
  }

  override func scene(_ scene: UIScene, openURLContexts URLContexts: Set<UIOpenURLContext>) {
    super.scene(scene, openURLContexts: URLContexts)
    URLContexts.forEach { SurfacesChannel.shared.open($0.url) }
  }
}
```

If FlutterSceneDelegate does not expose these as overridable in the Flutter version in use, implement them without `override` and without the super call.

11. flutter_local_notifications on iOS: in AppDelegate `application(_:didFinishLaunchingWithOptions:)` add `UNUserNotificationCenter.current().delegate = self as UNUserNotificationCenterDelegate` before the super call, as the plugin's README asks, so notifications show while the app is open and taps reach Dart.
12. `cd ios && pod install`, then `flutter build ios --debug --no-codesign` and run on a device (Live Activities need a device or an iOS 16.1+ simulator).
